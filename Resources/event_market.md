# 工程工作流事件市场

> 最后更新：2026-06-25
>
> 更新方式：按需手动触发
>
> 本次口径：不联网抓取最新事实，基于既有项目文档、PRD、需求上下文和稳定事件类型重构。未在本轮重新打开来源核验的条目，均标注为“需人工复核”。
>
> 读者：项目研发者本人，用于判断哪些外部事件会影响 Codex 工具管理、研发自动化、资料处理、嵌入式/硬件/机器人工作流。

## 1. 收录边界

本文件不再以“AI 行业发展本身”为中心，而以用户的工程工作身份为中心。事件只有在会影响工程工作流、工具选择、权限管理、来源策略、依赖风险或自动化闭环时才进入主表。

### 1.1 应收录

- Codex、Claude Code、GitHub Copilot、Cursor、Gemini CLI 等编码 agent 或开发工具的能力、权限、接口、计费、配置、验证方式变化。
- MCP、Plugins、Skills、工具调用、上下文文件、子代理、agent 配置和白名单生态变化。
- 会影响自动部署、版本固定、审计、回滚、凭据管理、安全合规的公告或漏洞。
- 浏览器、PDF、Word、Excel、网页资料、仓库级分析、长上下文工程文档处理相关能力变化。
- 嵌入式、硬件、FPGA、EDA、机器人、ROS、导航、数据手册和实验资料工作流相关的工具链变化。
- 官方迁移、废弃、别名切换、API 生命周期公告，因为这些会直接影响脚本、MCP、插件和自动化稳定性。

### 1.2 不收录为主事件

- 纯模型训练方法、微调技巧、模型榜单、benchmark-only 宣传。
- 消费娱乐功能、泛 AI 公司新闻、融资和组织变动，除非直接改变工程工具链。
- 只说明“模型更强”的旧版本发布。若后续版本已覆盖其工程意义，应移入“被覆盖或背景事件”。
- 无法落到本项目决策的泛趋势文章。

## 2. 来源可信度与复核状态

| 标记 | 含义 | 使用方式 |
|---|---|---|
| A | 官方公告、官方文档、官方 changelog、官方仓库 release | 可作为主事实来源，但仍需记录采集日期 |
| B | 高可信研究论文、标准组织、主流开发者平台公告 | 可辅助判断影响，重要事实尽量再找官方来源 |
| C | 项目上下文、人工推断、二级资料或未完全可验证来源 | 只能作为线索或低优先级观察 |

复核状态：

- `已核验`：本次更新中打开来源并确认关键事实、日期和链接可用。
- `需人工复核`：本次未联网或未打开来源，后续更新前必须重新确认。
- `被覆盖`：已有更新事件覆盖其主要工程意义，仅保留兼容、迁移或历史解释价值。
- `移除观察`：不再符合工程角色中心口径，后续不继续跟踪。

## 3. 高优先级工程相关事件

高优先级事件会直接影响本项目是否需要调整白名单、场景配置、部署验证、凭据边界、回滚策略或工程工作流。

### 3.1 编码 agent 与 Codex/Claude Code/Copilot/Cursor 的权限或执行模型变化

- 事件类型：编码 agent 新增或改变文件访问、命令执行、浏览器控制、子代理、长期任务执行、自动修复、PR/Issue 操作、IDE 接管等能力。
- 主要来源：
  - OpenAI Codex 官方文档或发布页。
  - Anthropic Claude Code 官方文档、MCP connector、Files/API/tool use 相关公告。
  - GitHub Blog、GitHub Changelog、Copilot 文档。
  - Cursor 官方 changelog。
  - Google Gemini CLI 或开发者工具官方仓库/文档。
- 来源可信度：A；本轮复核状态：需人工复核。
- 工程影响：这类变化会改变 agent 能做什么、能访问什么、失败后如何追踪，也会改变“哪些工具需要白名单批准”和“哪些验证层级必须执行”。
- 对本项目影响：需要同步检查 `Resources/tool_whitelist.toml`、`Resources/approval_review.toml`、场景配置和验证脚本，确认权限、依赖、最小功能调用与回滚记录仍匹配。
- 局限与复核重点：供应商发布页通常强调能力提升，不能替代本地验证。复核时必须确认版本、可用入口、权限模型、是否需要账号或 token、是否改变默认行为。

### 3.2 API 生命周期、模型别名、工具版本或服务废弃公告

- 事件类型：`latest` alias 切换、preview 模型停用、SDK 主版本升级、API 参数废弃、插件或 MCP server 改名、仓库归档。
- 主要来源：
  - Google AI Developers Forum 或 Gemini API 官方文档。
  - OpenAI、Anthropic、GitHub、Microsoft、Cursor 官方 changelog。
  - 相关 SDK/MCP/插件官方 GitHub release。
- 来源可信度：A；本轮复核状态：需人工复核。
- 工程影响：这类事件会导致原本可用的自动化脚本在未改代码的情况下变慢、变贵、失败或输出质量变化。
- 对本项目影响：白名单条目必须固定版本、commit 或明确 release；不得把 floating alias 当作可审计版本。市场更新时应触发“升级建议”，而不是自动修改批准状态。
- 局限与复核重点：论坛帖、issue 和讨论区可能包含用户反馈，不能当作官方性能结论。正式记录应优先引用官方迁移页或 release note。

### 3.3 MCP、Plugins、Skills 生态的安装、发现和安全边界变化

- 事件类型：MCP 协议、官方 server、插件仓库、技能安装方式、manifest schema、权限声明、签名或来源验证机制发生变化。
- 主要来源：
  - Model Context Protocol 官方站点、规范仓库和 GitHub release。
  - OpenAI Plugins 官方仓库和 Codex 插件缓存 manifest。
  - Codex Skills 相关官方文档或本地技能说明。
- 来源可信度：A；本轮复核状态：需人工复核。
- 工程影响：这类事件决定工具是否能被 Codex 发现、安装、验证和最小调用，也决定白名单字段是否需要扩展。
- 对本项目影响：需要更新 `Resources/plugins_market.md`、`Resources/MCP_market.md`、`Resources/tool_market.md` 和审批辅助表；若 manifest 或权限模型变化，自动部署逻辑也需要跟进。
- 局限与复核重点：本地 `/plugins` UI、CLI、缓存和 GitHub 仓库可能不同步。复核时必须记录来源差异，不能把单一来源当作完整市场。

### 3.4 凭据、安全、供应链和企业治理相关事件

- 事件类型：开发工具供应链漏洞、token 泄露风险、自动化执行越权、插件签名/完整性校验变化、企业审计策略变化。
- 主要来源：
  - 官方安全公告。
  - GitHub Security Advisory、CVE、供应商安全博客。
  - 插件/MCP/Skill 上游仓库的 security advisory 或 release note。
- 来源可信度：A/B；本轮复核状态：需人工复核。
- 工程影响：这类事件会直接影响是否允许自动部署、是否需要停用某个工具、是否需要重新生成凭据。
- 对本项目影响：若风险涉及已批准工具，应暂停自动部署，更新审批建议为 `needs_review` 或 `reject`，并在验证记录中说明影响范围。
- 局限与复核重点：安全事件可能早期信息不完整。记录时应区分“已确认事实”和“待确认影响”，不得在日志中写入任何密钥、token 或 cookie。

## 4. 中优先级工具与生态变化

中优先级事件通常不会立即阻断项目运行，但会影响后续工具选择、市场文档维护和工程效率。

### 4.1 文档、浏览器、表格、演示和资料处理工具能力变化

- 事件类型：PDF/Word/Excel/网页读取与生成能力增强，浏览器自动化接口变化，文件型插件或技能更新。
- 主要来源：OpenAI/Anthropic/GitHub/Cursor/Google 官方工具文档，相关插件或技能仓库 release。
- 来源可信度：A；本轮复核状态：需人工复核。
- 工程影响：影响数据手册、规格书、BOM、测试报告、会议材料和长文档整理效率。
- 对本项目影响：可能改变 `Resources/config_file.toml` 和文件场景的最小充分工具集，也可能要求增加更细的输出验证。
- 局限与复核重点：能力宣传不等于格式保真。涉及文档生成时，应要求渲染或打开验证，而不只检查文件存在。

### 4.2 GitHub、仓库操作和自动化协作流程变化

- 事件类型：GitHub Copilot、Issues、PR、Actions、Code Search、Dependabot 或 repo automation 的 agent 化能力变化。
- 主要来源：GitHub Blog、GitHub Changelog、GitHub Docs。
- 来源可信度：A；本轮复核状态：需人工复核。
- 工程影响：影响 agent 是否能创建 PR、关联 issue、执行检查、读取仓库上下文和追踪提交证据。
- 对本项目影响：若后续实现 GitHub 追踪、自动 PR 或审批可视化，需要记录权限边界、审计事件和失败回滚方式。
- 局限与复核重点：产品 UI 能力、API 能力和 CLI 能力可能不同步。复核时应明确可自动化入口。

### 4.3 嵌入式、硬件、FPGA、EDA 和机器人开发工具链变化

- 事件类型：EDA 工具 AI 辅助、硬件文档检索、HDL/仿真辅助、ROS/机器人开发工具、边缘计算 SDK、板卡资料工具发生变化。
- 主要来源：芯片/EDA/机器人/开源工具官方公告、GitHub release、供应商文档。
- 来源可信度：A/B；本轮复核状态：需人工复核。
- 工程影响：影响数据手册阅读、接口约束整理、Verilog/VHDL 辅助、设备树、驱动和机器人软件调试效率。
- 对本项目影响：可能进入 `Resources/tool_market.md` 或场景配置，但只有在能被 Codex 调用、能部署或能稳定辅助资料处理时才应进入白名单建议。
- 局限与复核重点：很多硬件/EDA 工具依赖商业许可、Windows GUI 或专用环境，不能假设可自动部署。

## 5. 低优先级观察

低优先级事件只作为后续观察线索，不触发白名单或配置变更，除非后续出现明确工程影响。

| 观察方向 | 关注原因 | 当前处理 |
|---|---|---|
| 新模型能力宣传但未说明开发工具入口 | 可能未来影响编码质量，但当前不能直接转化为工具变更 | 不进入主事件，等待官方开发者工具或 API 变更 |
| 通用长上下文能力提升 | 可能影响仓库和资料处理，但需验证成本、延迟和准确性 | 低优先级观察 |
| 泛 AI 办公自动化产品 | 可能影响文档工作流，但通常与 Codex 工程闭环弱相关 | 仅在能接入文件场景时复核 |
| 学术论文中的 agent 行为研究 | 可作为治理和审计参考，但不能直接证明本项目提效 | 作为背景证据，不作为部署依据 |

## 6. 被覆盖或背景事件

旧事件不再默认保留在主事件区。只有当它解释迁移、兼容、权限或历史决策时才保留。

| 原事件或事件类型 | 当前处理 | 原因 | 后续动作 |
|---|---|---|---|
| 旧版通用模型发布，仅强调更强对话、写作或 benchmark | 移除观察 | 与工程工具链无直接关系，且容易被后续版本覆盖 | 仅当伴随 API 生命周期或工具权限变化时重新收录 |
| GPT-5.4/GPT-5.3 Instant 类旧版本能力发布记录 | 被覆盖 | 若存在更新工程版本，应只保留最新工程相关事件；旧版本不再作为主事件 | 后续复核官方来源，确认是否有仍有效的迁移或兼容风险 |
| 模型训练方式、微调策略、模型榜单 | 移除观察 | 不符合用户工程工作身份中心口径 | 不再跟踪，除非直接影响本项目工具部署或合规 |
| 2025 年工具栈基线事件 | 背景保留 | 可解释 MCP、文件访问、代码执行、IDE/GitHub 集成为何是 agent 工具栈基线 | 不计入 2026 主事件；仅在规则说明中引用 |

## 7. 手动更新规则

后续更新本文件时按以下流程执行：

1. 用户明确触发更新，并说明范围：全量、某供应商、某工具链、某时间段或某工程场景。
2. 先查官方来源：供应商发布页、开发者文档、changelog、GitHub release、安全公告。
3. 对每条候选记录以下字段：事件日期、主体、来源 URL、来源可信度、复核状态、工程影响、对本项目影响、局限。
4. 先套用工程角色过滤器：不能影响工具、权限、依赖、自动化、工程文档、嵌入式/硬件/机器人工作流的事件不进入主表。
5. 再套用覆盖规则：同一产品线的新事件完全覆盖旧事件时，旧事件移到“被覆盖或背景事件”，不继续占用主事件位置。
6. 对会影响已批准工具的事件，同步检查 `Resources/approval_review.toml` 和 `Resources/tool_whitelist.toml`，但不得自动改变批准状态。
7. 对会影响资料源策略的事件，同步检查 `Resources/plugins_market.md`、`Resources/github_market.md`、`Resources/MCP_market.md` 和 `Resources/tool_market.md`。
8. 本文件只记录事件和影响判断，不直接执行部署。部署仍必须走白名单、场景配置、验证和回滚流程。

## 8. 维护输出格式

新增主事件建议使用以下模板：

```markdown
### YYYY-MM-DD：事件标题

- 事件层级：高优先级工程相关 / 中优先级工具生态 / 低优先级观察
- 主体：公司、组织或项目
- 来源：官方或高可信 URL
- 来源可信度：A/B/C
- 复核状态：已核验/需人工复核/被覆盖/移除观察
- 客观事实：只写来源可支持的事实。
- 工程影响：说明对开发、资料处理、自动化、权限、合规或工具链的影响。
- 对本项目影响：说明是否影响市场文档、审批辅助表、白名单、场景配置、部署或验证。
- 局限：说明来源不完整、事实未复核、版本差异或本地验证缺口。
```

## 9. 当前结论

当前版本完成了事件市场的口径调整：优先跟踪会影响工程工作流和本项目闭环的事件；泛 AI 模型新闻、训练方法、微调技巧和榜单不再作为主事件。下一次手动更新时，应先从官方来源补充具体已核验事件，再按本文件规则维护覆盖关系。
